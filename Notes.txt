# Laravel Guard क्या होता है? (Hindi में समझें)

Laravel में **Guard का काम यह तय करना होता है कि आने वाली Request में User Login है या नहीं और किस Authentication System से Login है।**

आसान भाषा में:

- **Guard** → User को कैसे authenticate करना है?
- **Provider** → User का data कहाँ से लाना है?
- **Middleware** → कौन-सा route authenticated user access कर सकता है?

## 1. Laravel में Default Guard

Laravel में `config/auth.php` फाइल होती है।

```php
'defaults' => [
    'guard' => env('AUTH_GUARD', 'web'),
    'passwords' => env('AUTH_PASSWORD_BROKER', 'users'),
],
```

यहाँ `web` default guard है।

इसका मतलब Laravel सामान्यतः Session के जरिए User को authenticate करेगा।

### Guards Configuration

```php
'guards' => [
    'web' => [
        'driver' => 'session',
        'provider' => 'users',
    ],
],
```

यहाँ तीन बातें समझिए:

| Property | काम |
|---|---|
| `web` | Guard का नाम |
| `session` | Authentication कैसे maintain होगा |
| `users` | User का data किस provider से आएगा |

---

# 2. Guard और Provider में अंतर

मान लीजिए आपके School Management ERP में तीन प्रकार के users हैं:

1. Admin
2. Teacher
3. Student

आप चाहते हैं कि तीनों के login अलग-अलग हों।

उदाहरण:

```text
/admin/login
/teacher/login
/student/login
```

इसके लिए Laravel में अलग-अलग Guards बना सकते हैं।

### Step 1: config/auth.php

```php
'guards' => [

    'web' => [
        'driver' => 'session',
        'provider' => 'users',
    ],

    'admin' => [
        'driver' => 'session',
        'provider' => 'admins',
    ],

    'teacher' => [
        'driver' => 'session',
        'provider' => 'teachers',
    ],

    'student' => [
        'driver' => 'session',
        'provider' => 'students',
    ],

],
```

### Step 2: Providers Configure करें

```php
'providers' => [

    'users' => [
        'driver' => 'eloquent',
        'model' => App\Models\User::class,
    ],

    'admins' => [
        'driver' => 'eloquent',
        'model' => App\Models\Admin::class,
    ],

    'teachers' => [
        'driver' => 'eloquent',
        'model' => App\Models\Teacher::class,
    ],

    'students' => [
        'driver' => 'eloquent',
        'model' => App\Models\Student::class,
    ],

],
```

अब Laravel को पता है:

| Guard | Provider | Model | Table |
|---|---|---|---|
| web | users | User | users |
| admin | admins | Admin | admins |
| teacher | teachers | Teacher | teachers |
| student | students | Student | students |

ध्यान दें: Models में `Authenticatable` implementation होना चाहिए। Laravel का default User model यह सुविधा देता है।

# 3. Guard से Login कैसे करें?

### Admin Login

```php
use Illuminate\Support\Facades\Auth;

public function adminLogin(Request $request)
{
    $credentials = $request->validate([
        'email' => 'required|email',
        'password' => 'required',
    ]);

    if (Auth::guard('admin')->attempt($credentials)) {

        $request->session()->regenerate();

        return redirect('/admin/dashboard');
    }

    return back()->withErrors([
        'email' => 'Invalid credentials',
    ]);
}
```

यहाँ:

```php
Auth::guard('admin')->attempt($credentials);
```

Laravel `admin` guard के provider से Admin model का इस्तेमाल करके credentials verify करेगा।

### Teacher Login

```php
Auth::guard('teacher')->attempt($credentials);
```

### Student Login

```php
Auth::guard('student')->attempt($credentials);
```

# 7. क्या एक ही Users Table के लिए Multiple Guards बना सकते हैं?

**हाँ, बिल्कुल।**

मान लीजिए आपकी `users` table में:

| id | name | email | role |
|---|---|---|---|
| 1 | Kuldip | admin@gmail.com | admin |
| 2 | Rahul | teacher@gmail.com | teacher |
| 3 | Amit | student@gmail.com | student |

आपके पास केवल एक Model है:

```php
App\Models\User::class
```

अब `config/auth.php` में:

```php
'guards' => [

    'web' => [
        'driver' => 'session',
        'provider' => 'users',
    ],

    'admin' => [
        'driver' => 'session',
        'provider' => 'users',
    ],

    'teacher' => [
        'driver' => 'session',
        'provider' => 'users',
    ],

],
```

तीनों Guards एक ही `users` provider इस्तेमाल कर रहे हैं।

**लेकिन एक महत्वपूर्ण बात:**

```php
Auth::guard('admin')->attempt([
    'email' => $request->email,
    'password' => $request->password,
]);
```

यह अपने आप `role = admin` check नहीं करेगा।

इसके लिए:

```php
Auth::guard('admin')->attempt([
    'email' => $request->email,
    'password' => $request->password,
    'role' => 'admin',
]);
```

इसी तरह Teacher के लिए:

```php
Auth::guard('teacher')->attempt([
    'email' => $request->email,
    'password' => $request->password,
    'role' => 'teacher',
]);
```

इसके अतिरिक्त protected routes पर role-based authorization भी लागू करें। केवल guard का नाम `admin` रखने से user को admin permissions नहीं मिलतीं।

# 8. Guard और Role में सबसे बड़ा अंतर

यह Laravel Interview में महत्वपूर्ण सवाल है।

| Guard | Role |
|---|---|
| Authentication के लिए | Authorization के लिए |
| User Login है या नहीं | User क्या कर सकता है |
| `Auth::guard('admin')` | `$user->role === 'admin'` |
| Session या Token आधारित | Permissions आधारित |
| `config/auth.php` में configure | Database/Policies/Gates में manage |

### उदाहरण

```php
Auth::check();
```

यह बताता है कि User login है या नहीं।

जबकि:

```php
Auth::user()->role === 'admin';
```

यह बताता है कि User admin है या नहीं।

## 9. आपके Project के लिए मेरी सलाह

अगर आपके Laravel project में एक ही `users` table है और उसमें:

```php
role = admin
role = manager
role = user
```

तो **अलग-अलग Guards बनाना जरूरी नहीं है।**

आप एक ही `web` Guard रख सकते हैं और Roles के लिए Middleware या Laravel Policies इस्तेमाल कर सकते हैं।

लेकिन अगर आपके पास अलग-अलग tables हैं:

```text
admins
teachers
students
parents
```

तो अलग-अलग Guards उपयोगी हो सकते हैं।

### एक महत्वपूर्ण सवाल

आपके Laravel project में कौन-सा structure है?

**Option A:** एक ही `users` table है, जिसमें `role` column है।

**Option B:** `admins`, `users`, `managers` की अलग-अलग tables हैं।

इसके आधार पर मैं आपको **Laravel Guard + Provider + Middleware + Login का पूरा practical implementation** समझा सकता हूँ।


public function updateProfile($id, Request $request)
{
	/** @var \App\Models\User $user */
	$user = Auth::user();
	if (!$user) {
		return response()->json(['status' => false, 'message' => 'Unauthenticated'], 401);
	}
	$validator = Validator::make($request->all(), [
		'name' => 'required',
		'phone' => 'required',
		'avatar' => 'image|mimes:jpeg,png,jpg,webp|max:2048'
	]);
	if ($validator->fails()) {
		return edie([
			'status' => 'error',
			'message' => $validator->errors()->first(),
			'errors' => $validator->errors()
		], 200);
	}

	//dd($request->all());
	$user->name = $request->name;
	$user->phone = $request->phone;

	if ($request->hasFile('avatar')) {
		$image = $request->file('avatar');

		$imagePath = public_path('uploads/profiles/' . $user->avatar);

		if ($user->avatar && File::exists($imagePath)) {    File::delete($imagePath);     }

		$imageName = $user->id . '.' . $image->getClientOriginalExtension();
		$image->move(public_path('uploads/profiles'), $imageName);

		$user->avatar = $imageName;
	}

	$user->save();

	session()->flash('success', 'Profile Updated');

	return edie(['status' => 'success', 'message' => 'Profile Updated', 'reload' => 'reload']);
}

	Step-by-step samjho:
	$salesData = Order::select(
        DB::raw("DATE_FORMAT(created_at, '%d') as date"),
        DB::raw('SUM(grand_total) as total_sales')
    )
    ->where('created_at', '>=', Carbon::now()->subDays(6)->startOfDay())
    ->groupBy('date')
    ->orderBy('date', 'ASC')
    ->get();
	

	Part	Kaam
	Order::select(...)	orders table se data nikalna
	DATE_FORMAT(created_at, '%d')	created_at date ko sirf din (day number) me convert karta hai, e.g. 05, 12, 28
	as date	Us column ka alias date rakha
	SUM(grand_total) as total_sales	Har din ka total sales ka sum
	where('created_at', '>=', Carbon::now()->subDays(6)->startOfDay())	Aaj se 6 din pehle ki date ka start of day (00:00:00) se lekar ab tak ka data
	groupBy('date')	Day ke hisaab se group karo (jaise 05, 06, 07...)
	orderBy('date', 'ASC')	Din ascending order me sort karo
